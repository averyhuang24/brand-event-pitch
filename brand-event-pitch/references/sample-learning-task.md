# 批量样本学习任务

当用户说“给你一个入口，自动学习里面所有招商飞书文档和 PPT”时，按本文执行。目标不是收藏样本，而是从样本中提炼可迁移的招商判断、结构、页面模块、文档格式和视觉规律。

## 入口协议

用户可以给以下任一种入口：

- 飞书/豆包文档、知识库、文件夹、云盘目录、PPT/Slides 链接
- 一个包含多份招商文档的飞书文件夹或知识库节点
- 本地导出的 DOCX、Markdown、PDF、PPTX、图片目录
- 多个入口的清单

如果入口是单篇文档，只学习这篇。如果入口是目录或知识库节点，默认递归学习其下所有可访问的招商相关文档、幻灯片、PDF、PPTX 和图片型方案。不要跨出用户给定入口范围。

如果入口是一个“总文档”，正文里用 `@文档` 或链接集中列出样本，先把这些引用当作 corpus 清单处理。学习前必须按真实文档 token 去重，保留第一次出现的样本；如果用户要求清理总文档，可以删除后续重复引用块，但只删除明确重复的链接段落。

如果入口范围可能很大，先问一个决策问题：是否学习全部，还是只学习招商相关文件。默认选择“只学习招商相关文件”。

## 访问顺序

优先使用当前环境中的飞书/Lark 工具读取私有内容：

1. 云盘、文件夹、知识库入口：先列出文件清单和层级。
2. 文档/Docx：读取正文、标题层级、表格、图片说明。
3. Slides/PPT：读取每页标题、正文、备注、可提取图片信息；不能读正文时导出或请求用户提供 PPTX/PDF。
4. PDF/图片型文件：先抽取可读文字；文字不足时作为视觉样本，记录封面、页序、版式、信息密度、图表/权益页形态。
5. 无权限或工具不可用：明确说明卡点，请用户导出 Markdown、DOCX、PPTX、PDF 或页面截图。

不要用网页浏览假装读取私有飞书内容。

## 清单阶段

先生成一个临时 corpus manifest，用于控制范围，不直接写入发布版 references。每个样本记录：

```text
source_id: 可回溯的短 ID，不暴露完整私密链接
title: 文档标题
format: docx/slides/pptx/pdf/image/unknown
path: 入口内相对路径
access_status: readable/partial/image_only/no_permission
sample_type: 大促节点/平台IP/情绪趋势/内容栏目/赛事/城市事件/招商手册/资源包/其它
learning_value: story/resource/rights/roadmap/document_format/visual/low
reason: 为什么值得学习或跳过
```

跳过明显无关文件，例如会议纪要、纯执行排期、素材源文件、空白模板、合同法务文件，除非用户明确要求也学习。

批量读取时应缓存本轮 manifest，避免重复拉取所有正文。缓存只用于本轮分析，不写入发布版 skill。推荐额外记录结构信号：

- heading_count
- table_count
- image_count
- source_count
- cite_count
- has_quick_info
- has_rights
- has_roadmap
- has_lock_or_order_flow
- has_package_ref

## 单样本提取

对每个可学习样本，提取以下信息：

- 项目类型：营销节点、平台 IP、内容栏目、线下事件、赛事、城市活动、招商手册等。
- 目标品牌：行业、品类、典型客户、合作档位。
- 第一性问题：它在回答“为什么现在、为什么这里、为什么这个 IP、为什么品牌进来”中的哪几个问题。
- 故事线：开场机会、平台证明、Big Idea、活动系统、品牌入口、资源承诺、成交路径。
- 页序/章节：保留抽象页面类型，不复制原文标题。
- 品牌进入方式：内容、达人、直播、搜索、货架、线下、IP 授权、PR、战报、共创等。
- 权益结构：档位、席位、排他、资源包、交付物、KPI 口径；价格只记录结构，不记录敏感具体数值，除非用户要求用于当前项目。
- 视觉规律：封面气质、主色倾向、版式密度、数据页、机制图、资源矩阵、权益表、roadmap 的表达方式。
- 可迁移规则：这个样本真正值得进入 skill 的方法论是什么。
- 不可迁移内容：只适用于该客户、该节点、该平台资源的内容。

对于飞书招商手册，正文优先级高于附件。正文通常已经包含招商速览、权益、锁单流程和资源包引用；附件常用于资源包、视频素材或视觉页补充。

## 聚类与归纳

不要把学习结论写成样本流水账。完成单样本提取后，至少做四类聚类：

1. **叙事模式**：哪些故事线反复有效，适合什么项目。
2. **页面/章节模块**：哪些页面承担关键决策功能，常见顺序是什么。
3. **权益与资源设计**：品牌为什么愿意买，销售为什么能谈。
4. **视觉与文档格式**：PPT、招商手册、飞书文档分别如何组织信息。

每条归纳必须能回答“以后生成招商方案时，这条规则会改变什么决策”。如果不能改变决策，不写入发布版学习结论。

附件聚类单独处理：

- PDF/PPTX 可下载且有可抽文字：提取页序、标题、权益表和 Roadmap。
- PDF/PPTX 是整页图片：只记录页数、尺寸、封面/权益页/Roadmap 等视觉形态；不要臆测文本。
- 视频素材：只记录为内容证明或传播素材，不进入方法论。
- 附件下载 403、无权限或工具不可用：标记为 unreadable，不阻塞正文学习。

## 输出产物

默认输出三份结果：

1. **学习覆盖摘要**：学了多少份，哪些可读，哪些只做视觉参考，哪些跳过，缺失什么权限。
2. **新增学习结论草案**：准备追加到 `references/sample-learnings.md` 的抽象规则。
3. **待合并建议**：哪些规则应合并进 `pitch-method.md`、`proposal-doc-method.md` 或 `SKILL.md` 主 workflow。

只有当用户同意“写入 skill”时，才修改 `references/sample-learnings.md` 或其它方法论文件。写入时只保留抽象方法，不保留完整原文、客户敏感信息、完整私密链接、报价明细或不可公开素材。

## 质量门

学习任务结束前检查：

- 是否覆盖了入口范围，而不是只看了最容易读的几份。
- 是否区分了 PPT、招商手册、资源包、执行文件。
- 是否先对总文档里的重复引用按 token 去重。
- 是否把重复样本聚类，而不是重复记录同一结论。
- 是否提炼了可迁移规则，而不是复述原文。
- 是否标出了权限失败、图片型文件和低置信结论。
- 是否保护了私密链接、客户信息、报价和不可公开素材。

## 用户启动句式

用户可以这样触发：

```text
启动 brand-event-pitch 样本学习任务。
入口：<飞书文件夹/知识库/文档/PPT 链接>
范围：只学习招商相关文件 / 全部学习
输出：先给学习摘要和可合并结论，不要直接写入 skill
```

如果用户只给入口，没有说明输出方式，默认先输出学习摘要和可合并结论，不直接写入 skill。
